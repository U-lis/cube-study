## E2E 테스트 (Playwright)

### T2-6. 조회 흐름

| # | 시나리오 | 기대 |
|---|---|---|
| 1 | `LB` 입력 | 기준공식 `LB`, `R D2 R' U R D2 R' U'`, 8수 표시 |
| 2 | 역 케이스 링크 클릭 | `BL` 화면으로 이동, URL `/?c=BL` |
| 3 | `/?c=TU` 직접 진입 | `TU` 결과 표시 |
| 4 | direct ↔ setup 토글 | 표시 알고리즘이 SPEC대로 전환 |
| 5 | strict ↔ compact 토글 | 괄호 유무가 전환 |
| 6 | `CU` setup 모드 | `(직접)` 배지 표시 |
| 7 | `LB` compact 모드 | `최종 무브 열이 같습니다` 배지 (sameAlg) |
| 8 | `LB` strict 모드 | 위 배지 없음 |

### T2-7. sticky 거동 (핵심)

| # | 시나리오 | 기대 |
|---|---|---|
| 1 | `LB` 입력 → 백스페이스 1회 | 결과가 **사라지지 않음**, `.stale` 클래스 부착 |
| 2 | 위 상태에서 결과 블록 위치 | 백스페이스 전후 `boundingBox().y` 동일 |
| 3 | 이어서 `C` 입력 (`LC`) | 결과가 `LC`로 교체, `.stale` 해제 |
| 4 | `LB` → 전체 삭제 | 결과 유지, 후보 목록 없음 |
| 5 | `L` 상태 | 후보 18개 표시 + 이전 결과 흐리게 유지 |
