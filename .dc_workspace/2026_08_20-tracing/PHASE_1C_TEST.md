# Phase 1C — 테스트 계획

## 테스트 커버리지 목표

좌표 매핑 순수부는 54칸 전수. 렌더링 자체는 단위 테스트로 확인하지 않는다 — Vitest node 환경에 WebGL 이
없다. 그림이 맞는지는 **체크리스트의 눈 확인** 과 Phase 5 의 E2E 가 본다.

## 실행 명령

```bash
pnpm test tests/unit/cube3d.test.ts
pnpm build && pnpm test tests/unit/bundle-three.test.ts
pnpm dev     # 눈 확인 (localhost)
```

눈 확인은 `http://localhost:5173` 으로 한다. LAN IP 는 쓰지 않는다.

`three` 를 import 하지 않는 순수부만 대상이다. 이 파일이 `three` 를 끌어오면 지연 로드 검사의 의미가
흐려진다.

(`speffz.ts:5-7` 의 면 순서 규약).

## 빌드 산출물 검사 (`tests/unit/bundle-three.test.ts`)

빌드가 없으면 skip 하지 말고 **실패** 시킨다.

| # | 검사 | 완료 조건 |
|---|---|---|
| 1 | 초기 청크(진입 스크립트와 그 정적 의존)에 `three` 가 없다 | 0건 (NFR-TR-2) |
| 2 | `three` 를 담은 청크가 별도 파일로 존재한다 | 1개 이상 |
| 3 | 소스에 `three` 정적 import 가 없다 | `grep -rn "from 'three'" src/` 가 `cube3d.ts` 한 곳 (그 파일 자체가 동적으로 로드된다) |
| 4 | `cube3d.ts` 를 부르는 곳이 전부 `await import(` | 정적 import 0건 |
| 5 | PWA precache manifest 에 `three` 청크가 포함된다 | 오프라인에서 3D 가 죽지 않는다 (NFR-TR-3) |
| 6 | 조회·기준공식·퀴즈 화면의 초기 스크립트 목록이 변경 전과 같은 집합이다 | `three` 유입 0건 |

**#1 의 방법**: `build/index.html`(또는 `.svelte-kit/output/client/`)이 참조하는 진입 스크립트에서 시작해
정적 import 그래프를 따라가며 파일명·내용을 확인한다. 그래프 추적이 과하면 최소한 "진입 청크와 그 직접
의존에 `three` 문자열이 없다" 로 대신하되, 무엇으로 확인했는지 주석에 남긴다.
