- 화면을 벗어나면 워커가 `terminate()` 된다

## 수정·생성할 파일

### `src/routes/trace/+page.svelte` (신규)

세션 상태 기계를 이 파일이 소유한다.

```
idle ──시작──> tracing ──(follow: 마지막 입력 / memorize: "다 외웠다")──> input ──채점──> result
 ↑                                                                                    │
 └────────────────────────── 다음 문제 ───────────────────────────────────────────────┘
```

| 단계 | 큐브 | 타이머 | 입력 |
|---|---|---|---|
| `idle` | **전 면 회색** (회전 가능) | 정지, `0.00` | 비활성 |
| `tracing` | 스크램블 색 | **흐른다** | `follow` 는 활성, `memorize` 는 비활성 |
| `input` | `follow` 는 보인다 / `memorize` 는 **사라진다** | 정지 (기록되는 값은 여기까지) | 활성 |
| `result` | 보인다 | 정지 | 비활성 |

**두 모드의 차이는 입력 시점에 큐브를 보여주는지 여부뿐이다** (FR-TR-21). 엔진도 채점도 같다.
`follow` 는 `tracing` 과 `input` 이 사실상 겹치고, `memorize` 는 "다 외웠다" 버튼이 둘을 가른다.

계시:

- 시작 = 색이 입혀지는 순간 (FR-TR-22)
- 종료 = `follow` 는 **마지막 타깃 입력**, `memorize` 는 **"다 외웠다" 를 누른 시점** (입력 시간은
  트레이싱 시간이 아니다)
- `performance.now()` 를 쓴다. `Date.now()` 는 시스템 시계 조정에 영향받는다 (FR-TR-23).
  기록의 `at` 필드만 `Date.now()` 다 (표시용 시각)

세션 설정(FR-TR-19, 21, 24)은 `tracing.svelte.ts` 싱글턴에서 읽고 쓴다. UI 는 기존 `SegToggle`
(`src/lib/ui/SegToggle.svelte`)을 재사용한다 — 대등한 두세 값의 세그먼티드 컨트롤이라 의미론이 맞는다.

`'both'`(코너 → 엣지)는 **한 스크램블에서 코너를 채점한 뒤 같은 스크램블로 엣지를 이어서** 한다. 실전이
그렇고, 그때 코너 파지가 가장 어려운 지점이 된다 (FR-TR-19). 기록은 조각 종류별로 각각 남는다.

스크램블 소스와 뷰어 연결:

```ts
const src = new ScrambleSource();
onMount(() => src.start());          // 워커 생성 + initSolver (백그라운드 1.7초)
onDestroy(() => src.dispose());      // terminate — 100MB 반납 (NFR-TR-1)
```

`src.ready` 가 `false` 인 동안 시작 버튼을 비활성하고 **"준비 중"** 을 표시한다 (FR-TR-2).

facelet 문자열은 `core` 로 만든 상태에서 뽑는다 (GLOBAL AD-10). 뷰어에 넘기는 색 배열은
`meta.colorScheme`(`types.ts:150`)로 매핑한다. 회색은 같은 경로에 회색 54칸을 넣는 것뿐이다 (FR-TR-22).

카메라: `setOrientation(Math.floor(Math.random() * 24))` 를 세션 시작마다 — 정확히는 `idle` 진입 시 —
호출한다. `idle` 에서 각도를 미리 잡아둘 수 있어야 하므로 시작 버튼이 각도를 다시 흔들면 안 된다.

## 프리렌더 주의 (GLOBAL AD-14)

`+layout.ts` 가 `prerender = true` 다. `/trace` 도 예외를 두지 않는다.

| 요소 | SSR | CSR |
|---|---|---|
| 3D 캔버스 자리 | 고정 종횡비 박스 (회색) | 같은 자리에 캔버스. **크기 불변** |
| 타이머 | `0.00`, `tabular-nums`, `min-width` 예약 | 숫자만 |
| 세션 설정 토글 | 전부 렌더 | 값만 |
| 시작 버튼 | 렌더 (disabled) | 활성화만 |
| "준비 중" 표시 | 렌더하지 않음 | `{#if browser && !ready}` 이중 방어 |
| 기록 목록 | 렌더하지 않음 | `{#if browser && records.length}` |

`{#if}` 로 큰 블록을 넣다 뺐다 하면 레이아웃이 점프한다. 이 저장소가 두 번 밟은 함정이다
(`src/routes/+page.svelte:33-46`).

## 이 페이즈에서 조심할 것

| 위험 | 대응 |
|---|---|
| 시작 전에 스크램블이 새어나감 | 색 배열을 `tracing` 진입 시점에 처음 만든다. `idle` 에서는 회색 배열만 존재 |
| 워커를 반납하지 않음 | `onDestroy` 에서 `dispose()`. E2E 로 관측 가능한 신호(예: 상태 플래그·`ready` 리셋)를 남긴다 |
| 타이머를 `Date.now()` 로 잼 | `performance.now()`. 시스템 시계 조정에 영향받는다 |
| `memorize` 에서 입력 시간까지 잼 | 종료 시점이 "다 외웠다" 다 |
| 하이드레이션 레이아웃 점프 | AD-14 표를 그대로 지킨다 |
| 카메라 각도가 시작 때 다시 흔들림 | `idle` 진입 시 한 번만. 사용자가 미리 잡아둔 각도를 뺏지 않는다 |
| 시간 제한을 넣고 싶어짐 | Out of Scope. 재기만 하고 제한하지 않는다 |
| E2E `@viewport` 태그 누락 | `tests/unit/e2e-tags.test.ts` 가 잡는다. 뷰포트 신호를 쓰면 태그를 붙인다 |
