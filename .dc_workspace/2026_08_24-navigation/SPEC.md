# 페이지 구성과 화면 흐름 - Specification

## 개요

앱에 **주제가 둘**이 되면서 정보 구조를 다시 세운다. 이슈 #27.

0.5.0 이 트레이싱 훈련을 넣으면서 앱은 성격이 다른 두 덩어리를 갖게 됐다.

```
공식  케이스 → 알고리즘        조회 · 기준공식 · 퀴즈
훈련  스크램블 → 타깃 열        트레이싱
```

지금 구조는 주제가 하나였을 때 만들어진 것이라 이 둘이 섞여 있다. **루트(`/`)가 조회 화면이면서 동시에 앱의 첫 화면**이고, 하단 탭은 네 기능을 같은 층위로 늘어놓는다. 서로 다른 일을 하러 온 사람이 같은 화면에 도착한다.

두 가지를 한다.

1. **진입점을 나눈다.** 홈을 따로 두고, 기능 화면끼리는 서로를 보여주지 않는다.
2. **기능 화면의 구성과 흐름을 통일한다.** 지금은 화면마다 제목의 뜻도, 설정의 자리도, 진행 버튼의 이름도 다르다.

**목표 버전**: 0.5.0 (마지막 스펙)

### 이슈 #27 의 유보를 뒤집는다

#27 은 "0.5.0 에서는 손대지 않는다" 로 적혀 있고, 착수 문턱을 **#19·#21 중 하나가 화면을 갖는 순간**으로 뒀다. 그 문턱은 아직 미달이다. 그런데도 지금 하는 이유가 둘이다.

- **세로 여백이 실제 제약이 됐다.** #28 에서 트레이싱 화면이 폭 390px 미만에서 43~71px 넘치는 것이 실측으로 나왔다. 하단 탭바는 모든 화면에서 52px 을 먹는다(`+layout.svelte:270`). 탭바를 "필요한 화면에만" 두는 것으로 트레이싱이 그 52px 을 돌려받는다 — 구조 정리가 곧 #28 의 부분 해결이다.
- **화면 규약을 지금 못 박아야 값이 싸다.** 0.5.0 의 트레이싱 작업에서 단계별 버튼·설정 접힘·판정 줄 규약이 새로 생겼다. 이것을 기존 화면에 퍼뜨리는 일은 화면이 4개인 지금이 가장 싸고, #19·#21·#23 이 붙은 뒤에는 7개가 된다.

## 지금 구조

| 라우트 | 화면 | 제목 | 설정 자리 | 흐름 |
|---|---|---|---|---|
| `/` | 조회 | `<h1>` 없음 | 없음 | 입력 → 결과(sticky) |
| `/anchors` | 기준공식 | `<h1>기준공식</h1>` | 없음 | 목록 → 상세 |
| `/anchors/[code]` | 기준 상세 | `<h1>{code}</h1>` + UpLink | 목록 머리 (`.toggles`) | 목록 |
| `/quiz` | 퀴즈 | `<h1>{case}</h1>` ← **문제다** | 화면 맨 위 (`.input-mode`) | 문제 → 입력 → 판정 → 다음 |
| `/trace` | 트레이싱 | `<h1>` 없음 | 시작 버튼 위, 시작하면 접힘 | 설정 → 시작 → 작업 → 채점 → 결과 → 다음 |

하단 탭은 `+layout.svelte:63-68` 의 배열 하나이고 네 항목이 `flex: 1` 이다.

**어긋나 있는 것 다섯 가지.**

1. `<h1>` 의 뜻이 화면마다 다르다 — 화면 이름(기준공식), 문제(퀴즈), 없음(조회·트레이싱)
2. 설정의 자리가 셋이다 — 맨 위(퀴즈), 목록 머리(기준 상세), 시작 버튼 위(트레이싱)
3. 진행 중 설정을 잠그는 규칙이 트레이싱에만 있다
4. 진행 버튼 이름이 갈린다 — `data-action="next"`(퀴즈) vs `data-next`(트레이싱)
5. 루트가 기능 화면이라 "앱을 열었다" 와 "조회를 하러 왔다" 가 구분되지 않는다

## 기능 요구사항 (FR)

### 홈과 카테고리

- [ ] **FR-NAV-1**: `/` 를 **홈**으로 바꾼다. 기능을 카테고리별로 묶어 나열하는 것이 전부이고, 기능 자체는 하나도 담지 않는다.
  - 지금 `/` 에 있는 조회 화면은 `/lookup` 으로 옮긴다.
  - 홈에는 **진도·통계 숫자를 넣지 않는다.** 각 화면이 이미 자기 숫자를 낸다(`/anchors` 의 암기 카운트). 홈이 그것을 다시 내면 데이터셋을 홈에서 읽어야 하고, 첫 화면의 로딩이 그만큼 늦어진다.
  - 환영 문구·카드·일러스트를 넣지 않는다 (NFR-9). 이름과 한 줄 설명이 전부다.

- [ ] **FR-NAV-2**: 카테고리는 둘이다. 이름과 소속을 아래로 고정한다.

  | 카테고리 | 기능 | 라우트 |
  |---|---|---|
  | **공식** | 조회 | `/lookup` |
  | | 기준공식 | `/anchors` (상세 `/anchors/[code]`) |
  | | 퀴즈 | `/quiz` |
  | **훈련** | 트레이싱 | `/trace` |

  - 카테고리 이름은 **사용자가 하는 일**로 짓는다. "공식" 은 케이스를 알고리즘으로 바꾸는 것을 배우는 곳, "훈련" 은 스크램블을 메모로 바꾸는 것을 연습하는 곳이다. 앱의 기존 어휘(기준공식·역공식)와 이어진다.
  - 카테고리 자체는 라우트를 갖지 않는다. `/공식` 같은 중간 페이지를 만들지 않는다 — 홈에서 기능으로 바로 간다. 중간 페이지는 탭을 하나 더 요구하면서 홈이 이미 낸 정보를 되풀이한다.

- [ ] **FR-NAV-3**: 홈의 각 기능 줄은 **이름 + 한 줄 설명**이다. 설명은 "무엇을 하는 곳인가" 를 적고, 잘하는 법이나 권유를 적지 않는다.

  ```
  공식
    조회        스티커 2글자로 알고리즘을 찾습니다
    기준공식     기준공식별 케이스 목록과 암기 진도
    퀴즈        케이스를 보고 알고리즘을 칩니다

  훈련
    트레이싱     스크램블에서 타깃 열을 뽑습니다
  ```

### 네비게이션

- [ ] **FR-NAV-4**: **하단 탭은 같은 카테고리의 형제만 담는다.** 다른 카테고리의 기능은 탭에 서지 않는다.
  - `/lookup` · `/anchors` · `/quiz` → `조회 | 기준공식 | 퀴즈` (3개)
  - `/trace` → 형제가 없다. **탭바를 그리지 않는다** (아래 FR-NAV-5)
  - 이것이 "서로 다른 기능이 한 페이지에 보이지 않게" 의 실제 구현이다. 퀴즈를 풀다가 트레이싱이 눈에 들어오지 않고, 그 반대도 없다.

- [ ] **FR-NAV-5**: **형제가 하나뿐이면 탭바를 그리지 않는다.** 자기 자신만 있는 탭바는 이동 수단이 아니라 장식이다.
  - 트레이싱이 여기 해당한다. 52px 을 돌려받고, 그만큼 #28 의 "한 화면에" 가 쉬워진다.
  - #19(문자 훈련)·#21(메모 훈련)이 들어오면 훈련 카테고리의 형제가 늘어 탭바가 저절로 생긴다. 그때 이 규칙을 고칠 필요가 없다.

- [ ] **FR-NAV-6**: 홈에는 탭바가 없다. 홈이 곧 지도다.

- [ ] **FR-NAV-7**: 모든 기능 화면 맨 위에 **홈으로 돌아가는 링크**를 둔다. 기존 `UpLink` 를 쓴다 (`src/lib/ui/UpLink.svelte`, 이미 `/` 와 `/anchors/[code]` 가 쓴다).
  - 라벨은 카테고리 이름이 아니라 **홈**이다. 카테고리는 라우트가 없으므로 되돌아갈 자리가 아니다.
  - `/anchors/[code]` 만 예외로 `기준공식` 으로 올라간다 — 목록의 항목이라 상위가 홈이 아니라 목록이다.

### 화면 공통 구성

- [ ] **FR-NAV-8**: 모든 기능 화면은 아래 순서를 지킨다. 없는 칸은 건너뛰되 **순서를 바꾸지 않는다.**

  ```
  1. 되돌아가기      UpLink — 어디서 왔는가
  2. 화면 이름       <h1> — 이 화면이 무엇인가
  3. 설정           이 화면의 동작을 정하는 토글
  4. 본문           입력·조작·목록
  5. 판정            한 줄 결과
  6. 결과 상세       판정을 뒷받침하는 사실
  7. 형제 탭         (형제가 둘 이상일 때만)
  ```

- [ ] **FR-NAV-9**: `<h1>` 은 **화면 이름**이고 화면당 하나다.
  - 퀴즈의 `<h1>{current.case}</h1>` 를 고친다. 케이스 코드는 문제이지 화면 이름이 아니다 — `<h1>퀴즈</h1>` 를 세우고 케이스는 본문의 요소로 내린다.
  - 조회(`/lookup`)와 트레이싱에 `<h1>` 을 세운다. 지금 둘 다 없다.
  - **제목 줄이 세로를 먹는 것을 감수한다.** 대신 트레이싱은 탭바 52px 을 돌려받으므로 순증이 아니다.

- [ ] **FR-NAV-10**: 설정은 **제목 바로 아래, 본문 위**다. 세 화면이 지금 서로 다른 자리에 두고 있다.
  - `/anchors/[code]` 의 `.toggles`(암기 숨김·역공식 숨김)를 목록 머리에서 제목 아래로 올린다.
  - 트레이싱은 0.5.0 작업에서 이미 이 자리다.

- [ ] **FR-NAV-11**: **한 판이 진행 중이면 그 판의 조건을 정하는 설정은 접고 잠근다.** 판이 끝나 다음으로 넘어갈 때 풀린다.
  - 트레이싱이 0.5.0 에서 만든 규칙을 규약으로 올린다 (`data-locked`, `.trace:not([data-stage='idle']) .settings { display: none }`).
  - **퀴즈에도 적용한다.** 입력 모드(`settings.quizInput`)는 그 문제의 조건이다. 답을 치는 도중에 바뀌면 이미 친 입력의 뜻이 흔들린다. 첫 입력에서 잠그고 "다음 문제" 에서 푼다.
  - 기준 상세의 두 토글은 **해당하지 않는다.** 표시 방식이지 판의 조건이 아니고, 목록을 보는 도중에 바꾸는 것이 정상 사용이다.
  - 접는 것과 잠그는 것은 따로다. 접는 것은 CSS(눈), 잠그는 것은 `disabled`(값)다. CSS 가 뜻대로 안 먹는 자리가 있으므로 둘 다 한다.

- [ ] **FR-NAV-12**: 판정 줄의 표기를 규약으로 못 박는다. 퀴즈와 트레이싱이 이미 같은 값을 쓰고 있다 — 문서가 없을 뿐이다.
  - 요소: `data-verdict`, `data-kind={판정 종류}`, `data-result={'ok' | 'bad' | ''}`
  - 색: `--ok` / `--danger`. **색만으로 알리지 않는다** — 같은 줄에 판정 문구가 함께 선다 (#26)
  - 판정이 없는 동안 상자를 그리지 않는다. 자리는 지키되 빈 상자를 두지 않는다.

- [ ] **FR-NAV-13**: 진행 버튼의 이름과 자리를 통일한다.

  **두 종류를 구분한다.** 지금 `data-action` 이 둘을 겸하고 있어서 어긋나 보인다.

  | 종류 | 규약 | 지금 |
  |---|---|---|
  | 입력 패드 안의 **편집** 동작 | `data-action="…"` | 이미 일관됨 — `undo`·`clear`·`back`·`separator` (`MoveKeypad.svelte:42,45`, `StickerPad.svelte:113,121,135`, `CaseInput.svelte:85`). **손대지 않는다** |
  | 화면의 **진행** 버튼 | `data-{동작}` | 갈려 있다 — 트레이싱 `data-start`·`data-memorized`·`data-grade`·`data-next` vs 퀴즈 `data-action="next"`·`data-action="submit"` |

  - 퀴즈를 진행 규약으로 옮긴다. `data-action="submit"` → `data-grade` (제출해서 채점하는 같은 동작이다), `data-action="next"` → `data-next` (`quiz/+page.svelte:253,263`).
  - 자리: 본문과 판정 사이. **단계마다 실제로 누를 수 있는 버튼 하나만 보인다** (트레이싱이 0.5.0 에서 만든 규칙).
  - 최소 높이 44px 을 유지한다 (FR-MC-4).

### 흐름

- [ ] **FR-NAV-14**: 훈련형 화면(퀴즈·트레이싱, 앞으로 #19·#21)의 단계 이름을 통일한다. 화면이 필요 없는 단계는 건너뛰되 **이름을 다르게 짓지 않는다.**

  ```
  idle → active → input → result → (다음) → idle
  ```

  | 단계 | 뜻 | 퀴즈 | 트레이싱 |
  |---|---|---|---|
  | `idle` | 설정을 고르고 시작을 기다린다 | **없음** — 문제가 늘 떠 있다 | 있음 |
  | `active` | 문제가 제시된 상태 | 있음 | 트레이싱 중 |
  | `input` | 답을 치는 중 | 있음(`active` 와 겹침) | 겹치거나(follow) 분리(memorize) |
  | `result` | 채점 결과를 본다 | 있음 | 있음 |

  - **퀴즈에 `idle` 을 만들지 않는다.** 퀴즈는 연달아 푸는 화면이라 문제마다 시작 버튼을 누르게 하면 흐름이 끊긴다. 단계 이름을 공유하는 것과 단계를 강제하는 것은 다르다.
  - 화면 루트 요소에 `data-stage` 를 싣는다. 검사와 CSS 가 같은 신호를 본다.

### 규약의 자리와 강제

지금까지 규약이 안 지켜진 이유는 규약이 없어서가 아니라 **규약이 일회용 문서 안에 흩어져 있어서**다. 프리렌더 불변 원칙은 `2026_08_08/GLOBAL.md` 의 AD-4 로 처음 적혔고, 트레이싱이 그것을 AD-14 로 다시 적었고, 코드 주석이 또 적고 있다. 매 작업이 같은 규칙을 다시 유도한다.

- [ ] **FR-NAV-15**: **`.dc_workspace/CONVENTIONS.md`** 를 신설한다. 화면을 만들 때 지켜야 하는 것을 한곳에 모으고, **각 규칙마다 근거와 그 규칙이 없어서 겪은 사고를 함께 적는다.**
  - **자리는 `BACKLOG.md` 의 선례를 따른다.** `.dc_workspace/BACKLOG.md` 가 이미 "작업 단위를 넘어 살아남는 문서" 로 그 폴더에 평평하게 있고, `dotclaude-config` 헤더 없이 그냥 마크다운이다. `README.md:111` 이 이미 `.dc_workspace/` 를 설계 근거의 자리로 가리키고 있으므로 새 규약을 세울 것이 없다.
  - 옮겨 올 `GLOBAL.md` 들이 전부 `.dc_workspace/*/` 안에 있다. 정본과 출처가 같은 폴더에 있는 편이 대조하기 쉽다.
  - **`.claude/` 에 두지 않는다.** `.gitignore` 가 그 폴더를 제외하고 있어(`# AI` 절) 커밋되지 않는다 — 규약이 사람 사이에 공유되지 않으면 규약이 아니다.
  - 흩어져 있는 것을 **옮기는 것이지 새로 쓰는 것이 아니다.** 아래 표가 출처다.

    | 규약 | 지금 있는 곳 |
    |---|---|
    | 프리렌더/하이드레이션 요소 개수·크기 불변 | `2026_08_08/GLOBAL.md` AD-4, `2026_08_20/GLOBAL.md` AD-14, 코드 주석 다수 |
    | UI 문구는 사실만 — 백분율·격려·게이미피케이션 금지 | NFR-9, `2026_08_03/GLOBAL.md` 6절 |
    | 색만으로 정보를 전달하지 않는다 (이중 부호화) | #26, `quiz`·`trace` 코드 주석 |
    | 터치 타깃 최소 44px | FR-MC-4 |

## 결정 사항 (AD)

- **AD-NAV-1 — 카테고리에 라우트를 주지 않는다.** `/공식` 같은 중간 페이지는 탭을 하나 더 요구하면서 홈이 이미 낸 정보를 되풀이한다. 홈 → 기능이 언제나 한 번이다.

- **AD-NAV-2 — 조회를 `/lookup` 으로 옮긴다.** 루트를 홈으로 비우는 값이다. 치르는 비용은 아래 "이관 비용" 에 적는다.

- **AD-NAV-3 — `start_url` 은 `/` 로 둔다.** 설치된 앱을 열면 홈이 뜬다. 지금은 조회가 떴으므로 조회를 하러 온 사람에게는 탭이 하나 늘어난다. 그 값을 치르고 얻는 것이 "앱을 열었다" 와 "조회를 하러 왔다" 의 구분이다. **마지막 화면으로 복귀하는 방식(#27 후보 C)을 넣지 않는다** — 상태를 저장해야 하고, 첫 화면이 흔들리면 홈을 둔 이유가 사라진다.

- **AD-NAV-4 — 뒤로가기의 뜻을 바꾸지 않는다.** 설치된 앱에서 뒤로가기는 계속 "닫기" 하나만 뜻하고, 화면 이동은 `replaceState` 다 (`backguard.svelte.ts`). 홈이 생겼다고 "뒤로 = 홈" 으로 바꾸면 규칙이 둘이 되고, 그 둘의 경계를 사용자가 외워야 한다. 홈으로 가는 길은 언제나 화면 위의 링크다 (FR-NAV-7).
  - 브라우저 탭에서는 지금처럼 아무것도 가로채지 않는다.

- **AD-NAV-5 — 단계 이름은 공유하되 단계는 강제하지 않는다.** 퀴즈에 `idle` 을 만들지 않는 이유가 이것이다 (FR-NAV-14).

   2.1 단계 이름 idle → active → input → result, data-stage 로 노출
   2.2 단계 이름은 공유하되 단계를 강제하지 않는다
   2.3 한 판이 진행 중이면 그 판의 조건을 정하는 설정은 접고 잠근다
   2.4 접는 것(CSS)과 잠그는 것(disabled)은 따로 한다

## 3. 표기
   3.1 판정 줄 — data-verdict / data-kind / data-result
   3.2 진행 버튼 — data-{동작}. 패드 안 편집 버튼은 data-action
   3.3 색만으로 정보를 전달하지 않는다
   3.4 터치 타깃 최소 44px
   3.5 UI 문구는 사실만. 백분율·격려·게이미피케이션 금지
   3.6 한국어 UI, 큐브 표기와 케이스 코드는 영문

## 4. 렌더
