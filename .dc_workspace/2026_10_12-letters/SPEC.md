# 스티커 문자 훈련 - Specification

**Source Issue**: https://github.com/U-lis/cube-study/issues/19
**목표 버전**: 0.6.0 (마일스톤)
**작업 브랜치**: `feature/sticker-letters`

## 개요

3BLD 학습 앱(cube-study)에 **Speffz 문자 훈련**을 추가한다.

큐브를 보고 스티커를 문자로 읽지 못하면 어떤 3BLD 방법도 시작할 수 없다. 지금 앱은 그다음 단계만 다룬다. 3-style 조회·퀴즈는 "문자 쌍을 받으면 무엇을 치는가"이고, 트레이싱은 "스크램블에서 문자 열을 뽑는 것"이다. 그 둘이 전제하는 **"이 스티커는 무슨 문자인가"** 를 익히는 화면이 없다.

두 단계로 익힌다.

| 단계 | 상태 | 익히는 것 |
|---|---|---|
| 1단계 | 풀린 큐브 | 자리 ↔ 문자. "저 자리가 `A` 다. UBL 코너의 U면이다" |
| 2단계 | 섞인 큐브 | 색 ↔ 문자. 조각이 다른 자리에 가 있어도 색으로 정체를 읽는다. UB 엣지 조각은 어디에 있든 흰 면이 `A`, 파랑 면이 `Q` 다 |

트레이싱에서 실제로 쓰는 것은 2단계다. 버퍼에 있는 조각의 색을 보고 그 조각이 갈 곳의 문자를 읽는다. 1단계는 그 앞 단계다.

화면은 둘이다. **외우기**(`lookup`)는 문자가 찍힌 큐브를 돌려 보는 화면이고, **퀴즈**(`quiz`)는 색칠된 큐비 하나의 문자를 입력하는 화면이다. 결정 경위는 #19 댓글에 있다 (2026-10-12).

### 공통 — 3D 큐브

  - `src/lib/ui/Cube3D.svelte` 를 그대로 쓴다. `three` 지연 로드 규약도 그대로다 (NFR-LT-2).

  - 코너와 엣지는 같은 알파벳 A–X 를 쓴다. 화면이 다루는 문자는 언제나 고른 종류의 것이다.

### 외우기 (`lookup`)

- [ ] **FR-LT-7**: 풀린 큐브를 보여주고, **고른 종류(코너/엣지)의 스티커마다 Speffz 문자를 찍는다.** 다른 종류의 스티커와 센터에는 문자를 찍지 않는다.
  - 문자 ↔ 스티커 자리는 `src/lib/cube/speffz.ts` 의 `CORNER_INDEX` / `EDGE_INDEX` 가 정본이다. 이 좌표는 데이터의 `target1`/`target2` 756개와 대조해 검증된 값이다 (`tests/unit/speffz.test.ts`).

- [ ] **FR-LT-7a**: **설정은 토글 두 개다.**
  - 글자: 코너 / 엣지 (FR-LT-6)
  - 다른 조각: 회색 / 색. 글자가 없는 종류의 조각을 회색으로 가릴지, 실물처럼 색을 보일지 고른다

  | 글자 \ 다른 조각 | 회색 | 색 |
  |---|---|---|
  | 코너 | 코너만 색, 엣지는 회색 | 실물과 같다 |
  | 엣지 | 엣지만 색, 코너는 회색 | 실물과 같다 |

  - 글자가 찍힌 조각은 언제나 실제 색이다
  - **센터는 언제나 실제 색이다.** 기준 방향(FR-LT-8)이 센터로 보인다. 퀴즈(FR-LT-12)와 같다
  - "배경을 코너/엣지/둘다 중에서 고른다"는 안도 검토했다. 조합 여섯 중 둘이 글자가 찍힌 조각을 회색으로 가리고 다른 조각에 색을 보이는 판이었다. 쓸 일이 없는 판이라 "다른 조각" 토글로 바꿨다 (2026-10-12 사용자 결정). 조합 넷은 모두 쓸모가 있다

- [ ] **FR-LT-8**: **기준 방향을 화면에 글자로 적는다** — 앞면 초록, 윗면 흰색.
  - 색 이름은 코드에 박지 않고 데이터셋 `meta.colorScheme` 에서 읽는다 (`U: W`, `F: G` — `src/lib/data/corner-UBL.json:12`). 면과 색의 짝을 코드가 정하지 않는다는 규약(`src/lib/ui/facelets.ts:1-10`)을 따른다.

- [ ] **FR-LT-9**: **"원위치" 버튼**을 둔다. 누르면 카메라가 기준 방향(흰색 위·초록 앞)으로 돌아간다.
  - 카메라 방향 0번(`orientationOf(0)`, `src/lib/cube/cube3d-map.ts:105`)이 U·R·F 가 보이는 각도다.
  - **`Cube3D` 를 고쳐야 한다.** 지금은 `orientation` prop 이 바뀔 때만 카메라를 옮긴다 (`Cube3D.svelte:74`). 이미 0 인 값을 다시 0 으로 넣어도 아무 일이 없다. 리셋 수단이 따로 필요하다. 방식은 설계에서 정한다.
  - 진행 버튼이 아니다. 화면 규약상 진행 버튼은 "단계마다 하나"이고, 외우기에는 단계가 없다.

- [ ] **FR-LT-10**: **문자 표시 조건.** 글자가 또렷해야 하고, 흰·노랑·초록·파랑·빨강·주황 6색 위 어디에서나 잘 구분돼야 한다.
  - 회색 위에는 글자가 오지 않는다. 글자가 찍힌 조각은 언제나 실제 색이다 (FR-LT-7a).
  - 글자 색 하나로 6색 모두를 감당할 수 없으면 **외곽선**(글자 테두리) 등으로 대비를 확보한다. 예: 어두운 글자에 밝은 외곽선.
  - 페이지 테마(라이트/다크)와 무관하다. 글자는 스티커 위에 있다.
  - **`Cube3D` 에 새 기능이 필요하다.** 지금 `Mark` 는 `{ color, outline }` 뿐이라 글자를 찍지 못한다 (`src/lib/cube/cube3d-map.ts:40`).

- [ ] **FR-LT-11**: 외우기 화면에는 측정하는 판이 없다. 설정을 잠그지 않는다 (CLAUDE.md "기록을 안 남기는 화면은 잠그지 않는다").

### 퀴즈 (`quiz`)

- [ ] **FR-LT-12**: **문제 큐브의 칠.**
  - 센터 6개: 실제 색
  - 문제 큐비 하나: 실제 색
  - 그 밖의 스티커: 회색 (`GRAY`, `src/lib/ui/facelets.ts`)
  - 센터를 칠하는 이유: 전부 회색이면 1단계와 2단계 문제가 화면에서 구분되지 않는다. 센터가 위치 기준이 된다. 센터는 문제 큐비가 무엇인지 알려주지 않으므로 답이 새지 않는다.
  - **시험 삼아 가는 결정이다** (#19). 써 보고 어색하면 단계 구분을 없애 하나로 합치거나 다른 방식을 찾는다.
  - 위 칠은 "다른 큐비: 회색" 설정일 때다. "색" 설정은 FR-LT-12a.

- [ ] **FR-LT-12a**: **"다른 큐비" 토글: 회색 / 색.** "색"이면 문제 큐비 말고 모든 큐비가 실제 색으로 보인다. 실물을 보는 것과 같다 (2026-10-12 사용자 결정).
  - **글자는 어디에도 보이지 않는다.** 퀴즈는 두 설정 모두 문자를 찍지 않는다
  - **문제 큐비는 외곽선으로 구분한다.** 문제 큐비의 스티커에 `marks` 외곽선을 두른다 (`Mark = { color, outline }`, `src/lib/cube/cube3d-map.ts:40`). 트레이싱 결과 화면과 같은 수단이라 새로 만들 것이 없다
    - 스티커 색을 바꾸는 방식(다른 큐비를 흐리게 칠하기 등)은 쓰지 않는다. "실물과 같은 색"과 어긋난다
    - 외곽선은 색과 모양(`double` 등)이 함께 다르다. 색만으로 알리지 않는다는 규약을 지킨다
    - 외곽선 색은 6색 어느 스티커 위에서도 구분돼야 한다. 트레이싱의 `MARK_PALETTE` (`src/lib/domain/tracing.ts:811`)를 재사용할지, 이 화면 전용 값을 둘지는 설계에서 정한다
    - "회색" 설정에서도 외곽선을 두를지는 설계에서 정한다. 회색일 때는 색칠된 큐비가 그 자체로 표시다
  - 숨은 문제 큐비 안내(FR-LT-17)는 두 설정 모두에 적용된다. "색" 설정에서는 외곽선이 보이는 면 뒤에 있을 수 있다

- [ ] **FR-LT-13**: **단계 선택.** 설정 줄에 1단계(풀린) / 2단계(섞인) 토글을 둔다.
  - 1단계: 풀린 상태다. 문제 큐비는 제자리에 있다.
  - 2단계: 무작위 상태다. 문제 큐비는 다른 자리에 가 있거나 비틀려 있을 수 있다.
  - 2단계의 무작위 상태는 `cubejs` 의 `Cube.random()` 으로 만든다. 이 함수는 `lib/cube.js` 에 있어서(`node_modules/cubejs/lib/cube.js:266`) **풀이기 초기화(`initSolver`)와 Worker 가 필요 없다.** 사용자에게 스크램블 문자열을 보여주지 않으므로 생성기를 거칠 이유가 없다.
  - 조각을 우연히 제자리에 두는 상태도 2단계 문제로 유효하다.

- [ ] **FR-LT-14**: **답 입력.** 문제 큐비를 이루는 문자를 입력한다. 코너는 3개, 엣지는 2개다.
  - 입력은 `src/lib/ui/StickerPad.svelte`(24글자 온스크린 패드)를 쓴다. 고른 종류의 24글자를 낸다.
  - **채점은 확인(채점) 버튼을 누를 때 한다.** 입력 개수가 큐비의 문자 수(코너 3 · 엣지 2)에 이르기 전에는 버튼이 잠겨 있다. 다 찼다고 자동으로 채점하지 않는다 — 누르기 전에 고칠 수 있어야 한다.
  - 이 버튼이 이 단계의 진행 버튼이다. 판정 뒤에는 "다음 문제" 하나만 보인다 (화면 규약 "단계마다 누를 수 있는 것 하나").

- [ ] **FR-LT-15**: **채점: 순서는 상관없다.** `AQ` 와 `QA` 는 둘 다 정답이다.
  - 입력한 문자와 정답 큐비의 문자를 각각 오름차순으로 정렬해 비교한다.
  - 문자를 겹쳐 낸 답(`AA`)이나 개수가 틀린 답은 이 비교에서 저절로 오답이 된다. `Set` 비교는 중복을 접어 버리므로 쓰지 않는다.
  - 판정 함수는 **조각 종류를 인자로 받는다** (같은 알파벳 A–X 를 코너·엣지가 같이 쓴다).
  - 순수 함수로 `src/lib/domain/` 에 두고 단위 테스트한다.

- [ ] **FR-LT-16**: **판정 줄**은 화면 규약을 따른다 — `data-verdict` + `data-kind` + `data-result`. 색은 `data-result` 만 보고 칠하고, 같은 자리에 판정 문구가 함께 선다.
  - 오답일 때 정답 문자를 보여준다.

- [ ] **FR-LT-17**: **보이지 않는 문제 큐비 안내.** 문제 큐비가 처음 보이는 면 뒤에 있으면 화면이 거의 회색일 수 있다. 사용자가 버그로 오해할 수 있으므로 안내 문구를 둔다.
  - **보이는 면에만 문제를 내는 식으로 피하지 않는다.** 돌려서 찾는 것까지가 훈련이다 (#13 의 "돌려야 보이는 상태 유지"와 같은 원칙).
  - 안내 문구는 사실만 적는다. 문제 큐비가 어디 있는지는 알려주지 않는다.

- [ ] **FR-LT-18**: **퀴즈에는 원위치 버튼이 없다.** 퀴즈에서 외워야 할 것은 큐비가 무엇인지이고, 절대 위치로 다시 맞추는 것은 의미가 없다 (#19 결정).

- [ ] **FR-LT-19**: **출제.** 문제는 고른 종류의 큐비(코너 8 · 엣지 12) 중에서 뽑는다. 버퍼 큐비도 포함한다 — 버퍼 스티커에도 문자가 있다.
  - `src/lib/domain/quiz.ts` 의 `pickNext` 를 쓴다. pool 이 `RECENT_LIMIT`(20)보다 작으면 제외가 단계적으로 물러서므로(같은 파일 `pickNext` 주석) 그대로 동작한다.
  - 큐비를 무엇으로 식별할지(대표 문자 하나 / 큐비 이름)는 설계에서 정한다.

- [ ] **FR-LT-20**: 설정(코너/엣지, 단계, 다른 큐비)을 바꾸면 새 문제를 내고 입력을 비운다.

- [ ] **FR-LT-21**: 퀴즈는 기록을 남기지 않는다. 기존 3-style 퀴즈와 같다. 따라서 설정을 잠그지 않는다.

- [ ] **FR-LT-22**: 퀴즈의 처음 카메라 각도는 **24방향 중 무작위**다. 트레이싱의 `randomOrientation`(FR-TR-17)과 같다. 퀴즈에는 원위치가 없고, 색으로 읽는 훈련이라 기준 방향에서 시작할 이유가 없다.
  - 문제마다 새로 뽑는다. SSR 에서는 고정값이라 하이드레이션이 흔들리지 않게 한다 (트레이싱 `orientation` 처리와 같다).

### 화면 이름

- [ ] **FR-LT-24**: `lookup` 화면의 이름은 **외우기**다. 하단 탭 라벨·`<h1>`·`<title>` 이 모두 "외우기"다. `quiz` 는 "퀴즈"다.
  - `src/lib/ui/nav.ts` 의 `FEATURE_LABELS` 는 지금 기능 칸 → 라벨이 하나다(`lookup` → `조회`). **묶음별로 라벨을 덮어쓸 수 있게 고친다.** 3-style 의 `lookup` 은 계속 "조회"다.
  - 경로 칸 이름은 그대로 `lookup` 이다. 화면 이름만 다르다 (SVELTE.md 규칙 3 은 경로 칸 이름에 대한 규칙이다).

### 설정 저장

## 제약

- **룬만 쓴다.** `export let` · `$:` · `on:click` · `<slot>` · `svelte/store` 금지.
- **접기는 CSS 로 한다.** `{#if}` 로 DOM 에서 넣고 빼지 않는다 — SSR/CSR 요소 개수가 갈려 하이드레이션이 흔들린다. 이 저장소가 두 번 밟았다.
- **버퍼 리터럴을 엔진·도메인에 적지 않는다.** 이 기능은 버퍼를 쓰지 않지만, 출제 pool 을 만들 때 버퍼를 특별 취급하지 않는 것으로 지킨다.
- **자체 큐브 물리 금지.** 무작위 상태와 그 facelet 배치는 `cubejs` 가 낸다. 상태 → 54칸 색 변환은 `src/lib/ui/facelets.ts` 의 `faceletColors` 를 쓴다.
- **문자 ↔ 자리 표를 새로 만들지 않는다.** `speffz.ts` 하나만 쓴다.
- **E2E 테스트 제목에 템플릿 리터럴을 쓰지 않는다** (`tests/unit/e2e-tags.test.ts`).
- **기술 스택 고정**: SvelteKit 2 + Svelte 5 + TypeScript + `adapter-static` + `@vite-pwa/sveltekit`.
