## 2. 요구

### 서랍 (FR-DR)

- **FR-DR-1** 상단 바는 왼쪽 ☰, 오른쪽 화면 켜기 **(사용자)**. 설치 버튼은 지금처럼 조건부로 화면 켜기 앞에 선다. 테마·정보 버튼은 바에서 빠진다
- **FR-DR-2** 서랍 순서: 머리(앱 이름 · 버전) → 홈 → `3BLD` 묶음 → 설정 묶음(알림 · 테마 · 앱 정보)
- **FR-DR-3** 3BLD 아래 항목은 `nav.ts` 에서 계산한다. 형제 묶음(`SIBLING_GROUPS`)은 아코디언, 묶음이 없는 화면(트레이싱)은 바로 링크. 라벨은 `labelFor` 를 쓴다 — 하단 탭과 같은 표다
- **FR-DR-4** 묶음 이름 표: 스티커 문자 · 3-style 코너. 순서: 스티커 문자 → 3-style 코너 → 트레이싱 (외우는 순서: 문자 → 공식 → 실전)
- **FR-DR-5** 펼침은 저장하지 않는다. 서랍을 열 때 **지금 경로가 속한 묶음만** 편다. 나머지는 닫힌 채로 열린다 (navigation SPEC 3번 — 펼침을 기억하면 하이드레이션 예약 대상이 된다)
- **FR-DR-6** 묶음 머리는 링크가 아니라 접고 펴는 버튼이다 (`aria-expanded`). 경로 앞 칸은 화면이 아니다 (FR-NAV-2)
- **FR-DR-7** 지금 화면 항목은 `aria-current="page"` 와 함께 "지금 화면" 문구를 단다 (색만으로 알리지 않는다)
- **FR-DR-8** 설정 묶음의 줄은 오른쪽에 현재 값을 적는다. 알림: `매일 HH:MM` / `꺼짐` / `미지원`, 테마: `시스템`/`라이트`/`다크` (누르면 바로 순환, 서랍은 열린 채)
- **FR-DR-9** 앱 정보는 지금의 정보 모달을 그대로 연다 (서랍을 닫고 연다)
- **FR-DR-10** 서랍은 모달 `<dialog>` 다. 바깥 누름 · ESC · 닫기 버튼 · 항목 이동으로 닫힌다
- **FR-DR-11** 접기는 CSS 로 한다. 아코디언 내용은 언제나 DOM 에 있고 `hidden` 으로 감춘다 (`{#if}` 금지 규약)
- **FR-DR-12** 터치 타깃 44px 이상
- **FR-DR-13** 홈은 그대로 둔다. 홈은 "지도" 이고 서랍은 "어디서나 여는 지도" 다

### 알림 설정 (FR-NT)

- **FR-NT-1** 경로 `/settings/notify`. 앱 전역 설정은 라우트 축 밖 `/settings/*` 에 둔다 — 축 규칙의 예외가 아니라 일반 규칙이다 **(사용자)**. `/settings` 자체는 화면이 아니다(이름 공간)
- **FR-NT-2** 세로 순서는 화면 규약대로: 되돌아가기(홈) → `<h1>알림</h1>` → 설정(매일 퀴즈 켬/끔, 시각) → 본문(조건 알림 안내 · 이 기기 상태)
- **FR-NT-3** 켬은 사용자 제스처 안에서 `PushRelay.enable(meta)` 를 부른다. 끔은 `disable()`
- **FR-NT-4** 켜짐 여부의 정본은 릴레이 `state()` 다. 앱은 시각과 마지막으로 보낸 meta 만 저장한다 (bigsix ADR-29 와 같다)
- **FR-NT-5** 실패는 `Error.code` 별 사실 문구로 같은 자리에 적는다 (`unsupported` → "이 브라우저는 알림을 받을 수 없습니다" 등)
- **FR-NT-6** iOS 안내 한 줄: "iPhone 은 홈 화면에 추가한 앱에서만 알림이 옵니다"
- **FR-NT-7** 시각을 바꾸면 켜져 있을 때 곧바로 meta 를 다시 보낸다
- **FR-NT-8** 이 화면은 기록을 안 남기므로 설정을 잠그지 않는다

### meta 와 동기화 (FR-MT)

- **FR-MT-1** meta 모양:

  ```json
  { "v": 1, "tz": "Asia/Seoul", "daily": "21:00", "facts": { "lastQuiz": "2026-10-18" } }
  ```

  - `daily` — 매일 퀴즈 시각. `null` 이면 매일 퀴즈를 안 받는다 (구독은 조건 알림용으로 남는다)
  - `facts` — 조건 규칙이 읽는 **기기 사실**. 지금은 `lastQuiz`(코너 퀴즈를 마지막으로 채점한 현지 날짜) 하나. 규칙이 생길 때 칸이 는다
- **FR-MT-2** 직렬화 1024 바이트 이하 (연동 문서 §2)
- **FR-MT-3** 자동 동기화: 앱이 뜰 때, 그리고 퀴즈를 채점할 때 meta 를 다시 만든다. 직전에 보낸 것과 다르고 `state() === 'on'` 일 때만 `enable(meta)` 를 부른다 (권한이 이미 있으므로 제스처가 필요 없다). 실패는 조용히 넘긴다 — 다음 기회에 다시
- **FR-MT-4** `lastQuiz` 는 하루 한 번만 바뀐다. 채점마다 릴레이를 때리지 않는다
- **FR-MT-5** 릴레이 `client.js` 는 `app.html` 에 넣지 않는다. 설정 화면 진입·자동 동기화 때 한 번 붙인다 — 첫 화면·오프라인이 릴레이에 묶이지 않게 (bigsix NFR-35)

### 서비스워커 (FR-SW)

- **FR-SW-1** `strategies: 'injectManifest'`, 소스 `src/service-worker.ts`(SvelteKit 기본 자리), 출력 파일명 `sw.js` 그대로 (`sw.svelte.ts` 가 `/sw.js` 를 등록한다)
- **FR-SW-2** 0.5.0 사고를 막은 두 설정을 코드로 다시 만든다: `precacheAndRoute(…, { ignoreURLParametersMatching: [/.*/] })`, `NavigationRoute(createHandlerBoundToURL('/'))`
- **FR-SW-3** `skipWaiting` + `clients.claim` (autoUpdate 등가). `sw.svelte.ts` 의 새로고침이 그대로 돈다
- **FR-SW-4** 맨 위에서 `try { importScripts(RELAY + '/sw.js') } catch {}` — 릴레이에 닿지 않아도 앱 SW 설치는 성공한다
- **FR-SW-5** 앱 SW 는 `push`·`notificationclick` 을 갖지 않는다 (연동 문서 §3)
- **FR-SW-6** 릴레이 주소는 `PUBLIC_PUSH_RELAY_URL` — `.env.development`(dev 릴레이) · `.env.production`(prod 릴레이)

### 퀴즈 `?c=` (FR-QC)

- **FR-QC-1** `/3x3/bld/3style/corner/quiz?c=KG` 로 열면 `KG` 가 첫 문제다
- **FR-QC-2** "암기한 것만 출제" 가 켜져 있고 `KG` 가 그 밖이어도 **첫 문제는 KG 다** — 알림이 약속한 문제다. 다음 문제부터 출제 범위를 따른다
- **FR-QC-3** 데이터에 없는 코드면 무시하고 평소대로 출제한다
- **FR-QC-4** 쿼리는 읽고 나서 주소에서 지우지 않는다 (새로고침하면 같은 문제 — 북마크와 같다)

### 발송 cron (FR-CR)

- **FR-CR-1** 저장소 루트 `cron/`. `src/` 의 코드를 import 하지 않는다. 데이터 파일(`src/lib/data/corner-UBL.json`)은 읽는다 — 문제를 고르려면 케이스 목록이 있어야 하고, 사본을 두면 둘이 어긋난다
- **FR-CR-2** Node 24 `--experimental-strip-types` 로 돈다. 의존성 없음
- **FR-CR-3** 진입점 `cron/push.ts`
  - `tick --instance prod|dev` — 1분 타이머가 부른다. 구독 목록을 받아 규칙을 평가하고 보낸다
  - `send-now --instance … --title … [--body …] [--url …] [--to s_…] [--dedup …]` — 운영자 즉시 발송. `--to` 가 없으면 전체 구독
  - `--dry-run` — 보낼 메시지를 찍기만 한다
- **FR-CR-4** **규칙**: `{ id, evaluate(sub, ctx) → 메시지 | null }`. `ctx` 는 현재 UTC 와 케이스 목록. 규칙 목록 `cron/rules/index.ts` 하나에 모은다
  - `daily` (주기) — `[daily, daily+30분)` 창 안이면 보낸다. 창은 현지 자정에서 자른다. `dedupKey = daily:<현지 날짜>`
  - 조건 규칙 — **지금은 하나도 없다 (사용자: 필요할 때 "이때 푸시 보내" 로 정한다)**. 새 규칙은 파일 하나 + 목록 한 줄이다. 매 tick 평가되므로 조건이 맞는 그 분에 나간다. `dedupKey` 는 규칙이 정한다 (`<id>:<기간>`)
- **FR-CR-5** 한 구독에 한 tick 에서 여러 규칙이 맞으면 전부 보낸다. 같은 (구독, dedupKey) 는 릴레이가 8일 동안 한 번만 보낸다
- **FR-CR-6** ~~매일 퀴즈 메시지:~~ → FR-DQ-7 로 바뀌었다. 옛 내용: 제목 `코너 3-style 퀴즈`, 본문 `KG · DFR의 F면 → DFL의 L면`, `url` `/3x3/bld/3style/corner/quiz?c=KG`, `tag` `daily`, `badge` `/badge-face-96.png`, `icon` `/icon-192.png`. 문구는 사실만 **(사용자)**
- **FR-CR-7** ~~문제 고르기는~~ → FR-DQ-7 로 없어졌다. 옛 내용: 문제 고르기는 (구독 ID, 현지 날짜) 해시로 결정한다 — 창 안에서 재시도해도 같은 문제다
- **FR-CR-8** 검증 실패 meta 는 건너뛰고 로그에 남긴다. 3072 바이트를 넘는 메시지는 건너뛴다
- **FR-CR-9** `sent` 가 아닌 결과는 전부 로그에 남긴다. API 키는 로그에 안 남긴다 (연동 문서 §7)
- **FR-CR-10** `requestId` 는 보내기 전에 만들어 로그에 남긴다

### 매일 퀴즈 (FR-DQ) — 2026-10-19 추가

- **FR-DQ-1** 문제 수 5 ~ 20, 기본 10. `/settings/notify` 의 매일 퀴즈 칸에서 고른다 **(사용자)**. 기기 `localStorage`(`daily.size`)에만 둔다. 켬/끔·권한으로 잠그지 않는다 — 알림을 못 받는 기기도 화면은 쓴다
- **FR-DQ-2** 경로 `/3x3/bld/3style/corner/daily`, 하단 탭 이름 `매일` **(사용자)**. 범위는 코너 3-style 공식만 **(사용자)**. 범위가 여러 세트로 넓어지면 경로를 다시 본다
- **FR-DQ-3** 출제: 지금 입력 방식의 암기 체크에서 먼저 낸다. n 개 이상이면 그것만, 모자라면 나머지를 무작위로 채운다 **(사용자)**. 순서는 섞는다. 한 판 안에서 역쌍은 되도록 피하되 "외운 것 먼저" 를 이기지 않는다 (`src/lib/domain/daily.ts` `buildDailySet`)
- **FR-DQ-4** 다 풀고 한 번에 채점한다 **(사용자)**. 채점 전에는 이전/다음으로 오가며 답을 고칠 수 있다 **(사용자)** — 진행 버튼이 둘(이전 + 다음/채점)이 되는 것을 감수한다. 채점은 마지막 문제에서만 선다. 답이 없는 문제도 채점한다 (판정 `blank`)
- **FR-DQ-5** 단계 `idle`(입력 방식 · 안내 · 시작) → `active` → `result`. 결과가 그날 남으므로 측정하는 판이다 — 입력 방식은 `idle` 밖에서 접고 잠근다 (규약 2.3)
- **FR-DQ-6** 하루 한 판 **(사용자)**. 문제는 시작할 때 고르고 판(`daily.session`: 날짜·방식·문제·답·채점 여부)을 저장한다. 풀다 나가도, 채점 뒤 다시 열어도 그대로다. 지난 날짜의 판은 버리고 `idle` 로 연다. 판정은 저장하지 않는다 — 같은 답이면 같은 판정이다
- **FR-DQ-7** 알림은 문제를 고르지 않는다. 제목 `매일 퀴즈`, 본문 `코너 3-style`, `url` 은 FR-DQ-2 의 경로. 암기 목록은 기기에만 있어 cron 이 고를 수 없다 — 문제는 화면이 시작할 때 고른다. FR-CR-6 · FR-CR-7 · D-7 을 대신한다
- **FR-DQ-8** 채점하면 `push.noteQuiz()` — `facts.lastQuiz` 가 연습 퀴즈와 똑같이 갱신된다

## 3. 결정 (자리 비운 동안 내가 정한 것)

| # | 결정 | 근거 |
|---|---|---|
| D-1 | 서랍을 모달 `<dialog>` 로 만든다 | ESC·포커스 가두기를 브라우저에 맡긴다 (정보 모달과 같다). Android Chrome 은 모달 dialog 를 뒤로가기로 닫는다(CloseWatcher, Chrome 120+ — 2026-10-23 실기기 확인). 이러면 `backguard` 의 히스토리 감시 항목을 건드리지 않는다 |
| D-2 | `/settings` 화면은 만들지 않고 `/settings/notify` 만 | 서랍의 설정 묶음이 이미 목록 화면 노릇을 한다. 중간 경로에 화면을 두지 않는 규칙과도 맞다. 설정이 셋 이상 화면을 갖게 되면 다시 본다 |
| D-3 | 테마는 서랍 안에서 바로 순환 | 화면이 따로 필요 없는 세 값 순환이다. 바에서 빠져도 화면 색 자체가 상태를 보여준다 |
| D-4 | 이미 오늘 퀴즈를 푼 날에도 매일 퀴즈를 보낸다 | 예측 가능해야 한다 (bigsix H-3 과 같다). 건너뛰기는 "조건" 이므로 사용자가 정할 일 |
| D-5 | meta 에 `facts.lastQuiz` 만 미리 싣는다 | 조건 규칙의 가장 흔한 재료(안 푼 지 N일)를 지금 쌓아 두면, 규칙이 생기는 날 이미 데이터가 있다. 다른 사실은 규칙이 생길 때 |
| D-6 | 즉시 발송 CLI(`send-now`)를 둔다 | "조건이 되면 즉시" 의 가장 단순한 형태가 "운영자가 지금" 이다. 규칙을 만들기 전에도 실기기 확인에 쓴다 |
| D-7 | ~~알림 본문의 문제는 cron 이 고른다~~ (FR-DQ-7 로 대체) | 앱은 서버가 없어 알림 시점에 개입할 수 없다. 암기 범위는 기기 안에만 있으므로 전체 378 에서 고르고, FR-QC-2 로 그 문제를 반드시 낸다 |
| D-8 | 시각 입력은 `<input type="time">` | 폰 기본 시간 선택기가 뜬다. 분 단위 |

## 4. 알려진 한계

- **릴레이가 응답하지 않으면 앱 SW 업데이트가 미뤄질 수 있다.** 브라우저는 업데이트 검사 때 `importScripts` 한 스크립트도 다시 받는다. 릴레이에 못 닿으면 `registration.update()` 가 실패한다 — CI 러너에서 실제로 "업데이트 확인" 이 `확인하지 못했습니다` 로 끝났다 (PR #43 첫 CI). 앱은 옛 버전으로 계속 오프라인으로 돌고, 릴레이가 돌아오면 다음 검사에서 갱신된다. 처음 설치할 때 릴레이가 실패하는 것은 문제없다 (`try/catch`, `tests/e2e/quiz-pinned.spec.ts`). 릴레이 연동을 쓰는 한 피할 수 없다 (연동 문서 §3 이 이 방식을 정한다). bigsix 도 같다
- E2E 는 릴레이 주소를 `/__relay` 스텁으로 바꿔 빌드한다 (`playwright.config.ts`). 바깥 릴레이에 기대지 않는다
- iOS 는 홈 화면에 추가한 PWA(16.4+)에서만 알림이 온다. 홈서버가 꺼져 있으면 알림이 안 간다. 릴레이가 `Urgency` 를 안 보내 Android 절전 중에는 늦을 수 있다 (bigsix 에서 이어받음)
- 서랍을 Android 뒤로가기로 닫는 것은 Chrome 의 CloseWatcher 동작에 기댄다 (D-1). 실기기(Android)에서 닫히는 것을 확인했다 (사용자, 2026-10-23)
