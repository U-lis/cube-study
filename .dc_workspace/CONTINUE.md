## 2. 0.5.1 에서 한 것

트레이싱 훈련의 **설정 축을 하나로 합쳤다.** 근거는 `CHANGELOG.md` 의 `[0.5.1]`
항목과 커밋 `303f477` 에 있다.

| | 0.5.0 | 0.5.1 |
|---|---|---|
| 설정 줄 | 대상(3) + 치는 순서(2) | 훈련 대상(4) |
| 값 | `코너만`·`엣지만`·`코너+엣지` | `코너`·`엣지`·`코너→엣지`·`엣지→코너` |
| 화살표 뜻 | — | **외우는 순서** |
| 치는 순서 | 사용자가 고른다 | **모드가 정한다** — `외운 다음 입력` 은 역순, `보고 따라가기` 는 그대로 |

- 실전 3BLD 는 외운 순서의 역순으로 실행하고 통상 관례(CEEC)는 코너를 먼저
  외워 마지막에 푼다. 코너는 엣지를 *외우는* 동안이 아니라 엣지를 **실행하는
  내내** 붙들려 있고, 0.5.0 은 항상 코너부터 치게 해 그 구간이 빠져 있었다
- 암기와 같은 순서로 실행하는 연습은 **제공하지 않는다.** 역순이 표준이고,
  고를 수 있게 하면 훈련하지 않을 조합이 설정에 남는다
- `보고 따라가기` 만 뒤집지 않는 이유는 그 모드가 훑으며 한 조각씩 치는
  모드라 훑는 순서가 곧 입력 순서이기 때문이다. 뒤집으면 따라가기가 성립하지 않는다
- 개발 중 잠깐 토글이 셋이었다. 조합 여섯 중 둘이 같은 판이고, 그 한 줄이
  시작 버튼을 화면 밖으로 밀어냈다 (#28 과 같은 부류의 압력이다)

### 코드에서 어디를 보면 되나

| | |
|---|---|
| 순서를 정하는 유일한 곳 | `src/lib/domain/tracing.ts` 의 `entryKindsOf(target, mode)`. 배열은 그 아래 `kindsOf` 가 만든다 |
| 패드 글자·구분자 라벨·교차검증·채점 | 전부 그 배열에 **위치로** 매여 있어 배열만 뒤집으면 따라온다. 0.5.1 이 이들을 손대지 않은 이유다 |
| 설정 저장 | `src/lib/ui/tracing.svelte.ts` 의 `readTarget()` — `trace.target` 한 칸. 0.5.0 의 `trace.pieceKind`·`trace.entryFirst` 는 읽어서 옮기고 지운다 |
| 4지선다 토글 | `SegToggle` 의 `cols`. 넷을 한 줄에 넣으면 320px 에서 `코너→엣지` 가 `ellipsis` 로 조용히 잘린다 — 2×2 로 접고 검사로 못 박았다 |

### 기록 스키마는 안 건드렸다

`pieceKind` 는 여전히 `corner`/`edge`/`both` 이고 `entryFirst` 도 선택 필드로
남는다. 스키마 버전을 올리면 파서가 저장물을 통째로 버려 쌓인 50건이 날아간다.

### FR 번호를 바로잡았다

0.5.1 개발 중 이 기능에 붙은 `FR-TR-25` 는 SPEC 에서 **비틀림 표기** 항목이다.
훈련 대상은 `FR-TR-19` 이고, `2026_08_20-tracing/SPEC.md` 의 그 항목을 넷으로 고쳤다.

## 3. 0.5.0 에서 남은 지식

### 실측으로 잡은 것 (세로 맞춤)

- 큐브 높이 상한의 고정분이 **상단 바 49px 을 빠뜨리고 있었다** (26rem → 28rem)
- **정사각 영역은 폭에도 묶인다** — 390px 폭에서 큐브가 361px 이라 높이 계산이 안 닿는다
- 세로 맞춤 현황 (idle 문서 높이 / 진행 중 패드 아래끝). **0.5.1 에서 설정 줄이
  하나 줄었으므로 다시 재야 한다**

  | | idle | 진행 중 |
  |---|---|---|
  | 390×844 | 847/844 | 821/844 OK |
  | 412×915 | 915/915 OK | 843/915 OK |
  | 412×839 | 869/839 | 843/839 |
  | 375×667 | 704/667 | 678/667 |

  390 이상에서 "거의 스크롤 없음" 이 된다. 그 아래는 큐브가 하한(180px)에 가까워
  더 줄일 곳이 없다 → **#28**

### 되돌린 판단 하나

**엣지 버퍼에 토글을 붙인 것이 과했다.** 요구는 "DF 로 고정" 이었고, 고를 수 있는
반대편(UF)이 이 앱의 과정에 없으므로 아무도 안 누르는 선택지가 세로만 먹는다.
`e6fb839` 이 되돌렸고, `tests/e2e/trace-input.spec.ts` 에 **"버퍼를 고르는 토글이
화면에 없다"** 는 검사를 넣어 다시 생기는 것을 막았다.

### 라우트를 옮기다 잡은 사고 둘 (둘 다 배포에 영향)

**깊은 경로에서 자산이 404 였다.** `paths.relative` 기본값이 페이지 기준
상대경로를 내는데, 서비스워커가 `navigateFallback: '/'` 로 index.html 을 내주면
브라우저가 그것을 엉뚱한 깊이로 푼다. 라우트가 한 칸이던 0.4.2 까지는 우연히
맞아떨어졌다. `paths.relative: false` 로 고쳤다.

**`?c=` 가 붙은 주소가 홈으로 떨어졌다.** 프리캐시 키에 쿼리가 없어 이동 요청과
안 맞고, 그때 폴백이 `/` 다. `ignoreURLParametersMatching: [/.*/]` 로 고쳤다.

둘 다 서비스워커가 제어를 잡은 **두 번째 이동**에서만 드러난다. 배포 후 확인할 때
한 번 열어보고 끝내지 말 것 — 같은 주소를 두 번 열어야 한다.

## 6. 밟지 말 것

- **`{#if}` 로 화면 요소를 넣고 빼지 않는다.** SSR/CSR 요소 개수가 갈리면 하이드레이션이
  흔들린다. 이 저장소가 두 번 밟았다. 접는 것은 CSS 로 한다 (SPEC FR-NAV-18)
- **버퍼 리터럴을 엔진·도메인에 적지 않는다.** 정적 검사가 `src/lib/cube/trace.ts` 와
  `src/lib/domain/tracing.ts` 를 본다. 조립부(`src/routes/3x3/bld/trace/+page.svelte`)만
  알아도 된다
- **기록 스키마 버전을 함부로 올리지 않는다.** 파서가 불일치 시 저장물을 통째로 버린다.
  칸을 늘릴 때는 선택 필드로 두고 없는 기록을 되메운다
- **e2e 테스트 제목에 템플릿 리터럴을 쓰지 않는다.** `tests/unit/e2e-tags.test.ts` 의
  파서가 문자열 리터럴만 읽고, 제목을 못 읽으면 `@viewport` 태그도 못 읽어 그 테스트가
  mobile 프로젝트에서 조용히 빠진다
- **e2e 픽스처가 앱 기본값에 기대게 두지 않는다.** 엣지 버퍼 기본값을 바꿨을 때
  기대값이 통째로 어긋난 적이 있다. 전제는 픽스처가 적는다
- **합성 클릭(`dispatchEvent`)으로 `disabled` 를 확인하지 않는다.** 브라우저가 애초에
  배달하지 않는 이벤트라 사용자가 겪는 일과 무관한 답이 나온다
