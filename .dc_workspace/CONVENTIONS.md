# 화면 규약

이 저장소에서 화면을 만들 때 지키는 것. 각 항목은 **규칙 · 근거 · 검사** 세 줄이다.
검사가 "없음" 인 항목은 리뷰에서 사람이 본다.

**여기 있는 것은 옮겨 온 것이지 새로 쓴 것이 아니다.** 규약이 안 지켜진 이유는 규약이
없어서가 아니라 일회용 작업 문서마다 흩어져 있어서였다 — 프리렌더 불변 원칙은 GLOBAL
두 곳과 코드 주석에 세 번 적혔고, 그러고도 두 번 밟았다. 매 작업이 같은 규칙을 다시
유도하는 것을 여기서 끝낸다.

- **라우트 축과 프레임워크 사용 규약은 여기가 아니다** — `.dc_workspace/SVELTE.md`.
  새 화면의 URL 을 어디 앉힐지, 룬을 어떻게 쓸지는 그 문서가 정본이다.
- **데이터·도메인 함정은** `README.md` 의 "주의".
- 검사 칸은 파일과 검사 이름으로 적는다. 줄 번호는 금방 어긋난다.

## 1. 구조

### 1.1 화면은 자리가 고정된 영역의 세로 나열이다

- **규칙**: 영역의 순서를 바꾸지 않는다. 단계에 따라 서거나 접힐 뿐이고, 없는 영역은 건너뛴다. 순서는 — 되돌아가기 → `<h1>` 화면 이름 → 주 표시 → 계기 → 상태줄 → 설정 → 입력칸 → 자판 → 판정 → 결과 상세 → 진행 버튼 → 형제 탭.
- **근거**: 순서만 정하고 끝내려다 실패했다. 트레이싱 한 화면이 접었다 폈다 하는 곳만 다섯 군데라, 실제로 필요한 것은 **영역마다 자기가 설 단계를 선언하는 것**이었다 (`2026_08_24-navigation/SPEC.md` FR-NAV-8).
- **검사**: `tests/e2e/conventions.spec.ts` — 진행 버튼 자리. 단계별 표시/숨김은 `tests/e2e/trace-session.spec.ts`.

### 1.2 `<h1>` 은 화면 이름이고 화면당 하나다

- **규칙**: 문제나 데이터를 `<h1>` 에 넣지 않는다. 케이스 코드는 본문이다.
- **근거**: 0.4.2 까지 `<h1>` 의 뜻이 화면마다 달랐다 — 화면 이름(기준공식), 문제(퀴즈), 없음(조회·트레이싱). 클라이언트 이동에는 페이지 리로드가 없어서 SvelteKit 이 `<title>` 을 읽어주는데(접근성), `<h1>` 까지 뜻이 갈리면 화면의 정체가 어디에도 없다.
- **검사**: `tests/e2e/conventions.spec.ts` — "기능 화면의 h1 은 하나이고 화면 이름이다", "케이스 코드는 h1 이 아니다".

### 1.3 설정은 화면 이름과 본문 사이, 진행 버튼은 본문 최하단

- **규칙**: 고르고 나서 하는 순서가 그대로 세로 순서다. 진행 버튼은 그 단계에 보여줄 것을 다 보여준 다음에 선다.
- **근거**: 진행 버튼의 자리는 한동안 화면마다 갈려 있었다. `시작`·`채점`·`다음 문제` 를 한 자리로 만족시킬 수 없다고 보였는데, 접기 규칙(2.7)을 계산에 넣으면 풀린다 — `idle` 에서는 아래가 전부 접히므로 **최하단이 곧 설정 바로 아래**다. 덤으로 탭 순서가 읽고 → 채우고 → 진행이 된다 (SPEC AD-NAV-9).
- **예외 둘**:
  - **기준 상세의 두 토글**(암기 숨김·역공식 숨김)은 목록 머리에 남는다. 판의 조건이 아니라 목록 표시 필터라 목록 옆이 그 자리다.
  - **트레이싱의 세션 설정**은 큐브·계기·상태줄 아래에 선다. 큐브가 화면 이름 바로 아래 서는 것이 훈련의 성립 조건이라 그 사이에 설정을 끼울 수 없다.
- **검사**: `tests/e2e/conventions.spec.ts` — "퀴즈의 진행 버튼이 본문 최하단에 선다", "트레이싱의 진행 버튼이 본문 최하단에 선다". 설정 자리는 예외가 둘이라 자동 검사를 두지 않았다 — **검사 없음, 리뷰에서 본다.**

### 1.4 하단 탭은 형제만 담는다. 형제가 없으면 그리지 않는다

- **규칙**: 형제는 **경로에서 기능 칸만 다른 실재 화면**이다. 동적 세그먼트 화면(상세)은 그 칸을 걷어낸 경로로 계산해 목록의 탭을 물려받는다. 홈에는 탭이 없다.
- **근거**: 소속을 손으로 적은 배열은 화면이 늘 때마다 배열과 라우트 두 곳을 맞춰야 한다. 경로에서 읽으면 맞출 곳이 하나다 (SPEC FR-NAV-4·23). 자기 자신만 있는 탭바는 이동 수단이 아니라 장식이고, 트레이싱은 그 52px 을 돌려받아 한 화면에 들어가는 데 쓴다.
- **검사**: `tests/unit/nav.test.ts` (형제 계산·상세 물려받기), `tests/e2e/conventions.spec.ts` — "공식 화면 셋은 형제 탭 셋을 단다", "트레이싱에는 탭바가 없다".

### 1.5 기능 화면끼리 서로를 보여주지 않는다

- **규칙**: 공식 화면(`/3x3/bld/3style/corner/*`)에 트레이싱 링크를 두지 않고, 그 반대도 없다. 서로로 가는 길은 홈이다.
- **근거**: 서로 다른 일을 하러 온 사람이 같은 화면에 도착하지 않게 하는 것이 홈을 둔 이유다 (SPEC 개요).
- **검사**: `tests/e2e/conventions.spec.ts` — "공식 화면에 트레이싱으로 가는 링크가 없다", "홈은 넷을 모두 링크한다".

## 2. 흐름

### 2.1 단계 이름은 `idle → active → input → result`, `data-stage` 로 낸다

- **규칙**: 화면 루트에 `data-stage` 를 싣는다. 검사와 CSS 가 같은 신호를 본다.
- **근거**: 접기 규칙(2.7)이 전부 이 속성 하나에 달려 있다. 신호가 둘이면 화면과 검사가 다른 것을 보게 된다.
- **검사**: `tests/e2e/conventions.spec.ts` — "훈련형 화면은 data-stage 를 낸다".

### 2.2 단계 이름은 공유하되 단계를 강제하지 않는다

- **규칙**: 화면이 필요 없는 단계는 건너뛴다. 다만 **이름을 다르게 짓지 않는다.**
- **근거**: 퀴즈에 `idle` 을 만들지 않는다 — 연달아 푸는 화면이라 문제마다 시작을 누르게 하면 흐름이 끊긴다 (SPEC AD-NAV-5).
- **검사**: `tests/e2e/conventions.spec.ts` — "퀴즈에는 idle 이 없다".

### 2.3 측정하는 판이 도는 동안만 설정을 접고 잠근다

- **규칙**: 잠그는 기준은 "이 판의 결과가 기록으로 남는가" 다. 트레이싱은 잠그고, 퀴즈와 기준 상세는 잠그지 않는다.
- **근거**: 트레이싱은 초와 타깃 수를 기록에 남기므로(`msPerTarget` 의 분모) 도중에 조건이 바뀌면 그 기록이 무엇을 잰 값인지 알 수 없고 되돌릴 수도 없다. 퀴즈는 재지도 남기지도 않으므로 여러 표기를 오가며 푸는 것이 정상 사용이다 (SPEC AD-NAV-10).
- **검사**: `tests/e2e/trace-session.spec.ts` (트레이싱 잠금). 퀴즈는 "잠그지 않는다" 가 규칙이라 검사할 것이 없다.

### 2.4 접는 것(CSS)과 잠그는 것(`disabled`)은 따로 한다

- **규칙**: 접기는 눈에서만 지우고, 잠그기는 값을 지킨다. 둘을 한 수단으로 갈음하지 않는다.
- **근거**: 접기는 확대·리더 모드·사용자 스타일시트에서 뜻대로 안 먹을 수 있고, 그때 값을 지키는 것은 `disabled` 쪽이다. **합성 클릭(`dispatchEvent`)으로 `disabled` 를 확인하지 않는다** — 브라우저가 애초에 배달하지 않는 이벤트라 사용자가 겪는 일과 무관한 답이 나온다 (`trace-session.spec.ts` 의 해당 주석).
- **검사**: `tests/e2e/trace-session.spec.ts`.

### 2.5 단계로 안 갈리는 조건은 따로 속성으로 낸다

- **규칙**: `data-input-open` 처럼 별도 신호를 낸다. 그 판단을 CSS 안에서 되풀이하지 않는다.
- **근거**: 트레이싱의 채점 버튼이 그렇다 — `follow` 는 진행 중에 이미 입력이 열려 있고 `memorize` 는 "다 외웠다" 뒤에 열린다. 단계만으로는 안 갈린다.
- **검사**: 검사 없음 — 리뷰에서 본다.

### 2.6 단계가 바뀌어 화면이 짧아지면 스크롤을 원점으로 되돌린다

- **규칙**: `scrollTo({ top: 0 })`. `behavior` 를 지정하지 않는다 — 기본값이 사용자의 동작 감소 설정을 지킨다.
- **근거**: 시작 버튼을 누르는 시점에는 문서가 이미 내려와 있다. 그대로 설정이 접히면 주 표시의 윗부분이 잘린 채 시작된다.
- **검사**: `tests/e2e/trace-session.spec.ts` — "시작하면 화면이 맨 위로 되돌아간다".

## 3. 세로

### 3.1 접는 것이 기본이고, 자리를 예약하는 것이 예외다

- **규칙**: 판단 기준은 **그 영역의 표시 여부가 `localStorage` 나 브라우저 상태에서 오는가**. 오면 예약하고, `stage` 처럼 언제나 같은 값에서 시작하면 접는다.
- **근거**: "자리를 늘 잡아둔다" 는 옛 규칙의 진짜 근거는 하이드레이션 순간뿐이었다. 그 순간이 지나면 빈 자리는 낭비다. 트레이싱에서 이 규칙으로 접은 것이 시작 전 ~360px, 진행 중 ~270px 이다 (SPEC FR-NAV-18).
- **예외**: 퀴즈의 진행 버튼은 `{#if verdict}` 로 다른 버튼을 그린다. `verdict` 는 브라우저 상태가 아니라 SSR/CSR 이 갈릴 위험이 없고, "단계마다 누를 수 있는 것 하나만" 이라는 상위 규약은 지켜진다.
- **검사**: `tests/e2e/trace-session.spec.ts` (프리렌더 자리).

### 3.2 세로 예산은 가변 영역 하나가 흡수한다

- **규칙**: `max-width: clamp(하한, calc(100svh - 고정분), 상한)`. `vh` 줄을 먼저 두고 `svh` 줄로 덮어 `svh` 를 모르는 브라우저를 받는다.
- **근거**: 비율(`44vh`)로 묶으면 화면이 짧아질수록 **모자라게** 준다 — 아래 것들이 고정 높이라 그만큼 안 줄기 때문이다. 남는 자리를 그대로 주는 뺄셈이 맞다. `dvh` 는 스크롤 중에 값이 바뀌어 영역이 커졌다 작아진다.
- **검사**: 검사 없음 — 리뷰에서 본다.

### 3.3 고정분은 상단 바를 포함하고, 단계별 고정 높이 중 큰 쪽이다

- **규칙**: 화면 위에 무엇이 새로 서면 고정분을 그만큼 올린다.
- **근거**: 트레이싱의 고정분을 26rem 으로 적었다가 **상단 바 49px 을 빠뜨린 것**을 실측으로 잡았다. 0.5.0 의 화면 규약이 되돌아가기(44px)와 화면 이름(약 2.2rem)을 새로 세우면서 다시 32rem 으로 올랐다. 안 올리면 넘치는 쪽이 큐브가 아니라 화면이 된다.
- **검사**: 검사 없음 — 실측이다. `#28` 이 이 값을 추적한다.

### 3.4 정사각 영역은 폭에도 묶인다

- **규칙**: 높이 상한을 계산했어도 좁은 화면에서는 폭이 먼저 걸린다는 것을 잊지 않는다.
- **근거**: 390px 폭에서 큐브가 361px 이라 높이 계산이 닿지 않는다 (실측).
- **검사**: 검사 없음 — 리뷰에서 본다.

## 4. 표기

### 4.1 판정 줄 — `data-verdict` · `data-kind` · `data-result`

- **규칙**: `data-verdict` 는 존재만, 종류는 `data-kind`, 좋은 소식인지는 `data-result`(`ok`/`bad`/빈 문자열). 색은 `data-result` 하나만 보고 칠한다. 판정이 없는 동안 상자를 그리지 않는다.
- **근거**: 두 화면이 같은 것을 다르게 그리면 사용자가 판정을 두 번 배운다. 색 규칙을 종류마다 적으면 종류가 늘 때 CSS 도 는다 (SPEC FR-NAV-12).
- **검사**: `tests/e2e/conventions.spec.ts` — "퀴즈의 판정 줄이 규약 속성을 갖는다". 색은 `tests/e2e/quiz-feedback.spec.ts`.

### 4.2 진행 버튼 — `data-{동작}`. 자판 안 편집 버튼은 `data-action`

- **규칙**: 화면의 진행은 `data-start`·`data-grade`·`data-next`·`data-memorized`. 자판 안의 편집은 `data-action="undo|clear|back|separator"`. 단계마다 누를 수 있는 것 하나만 보인다.
- **근거**: 둘이 섞이면 "이 버튼이 어느 부류인가" 를 눌러봐야 알게 된다. **안 보이는 버튼은 상자가 없으므로 44px 검사는 각자 자기 단계에서 잰다** — 한 자리에서 넷을 재던 검사가 이 규칙 때문에 깨졌다.
- **검사**: `tests/unit/routes.test.ts` — "화면의 진행 버튼에 data-action 을 쓰지 않는다", "자판의 편집 버튼 이름은 그대로 둔다".

### 4.3 색만으로 정보를 전달하지 않는다

- **규칙**: 색이 말하는 것을 글자나 모양이 같은 자리에서 함께 말한다. 아이콘도 무엇을 가리키는지 스스로 말해야 한다.
- **근거**: 색각 이상 대비(#26). 눈 아이콘 둘이 나란히 있으면 글자를 읽어야 구분되던 것을 뇌·되돌이 화살표로 바꾼 것이 같은 이유다.
- **검사**: 검사 없음 — 리뷰에서 본다. (판정 색이 서로 다르다는 것만 `quiz-feedback.spec.ts` 가 본다.)

### 4.4 터치 타깃 최소 44px

- **규칙**: 누를 수 있는 것은 44px 이상. 보이는 크기는 그대로 두고 여백으로 채워도 된다.
- **근거**: FR-MC-4.
- **검사**: `tests/e2e/trace-session.spec.ts` — "버튼 터치 타깃이 44px 이상이다".

### 4.5 UI 문구는 사실만 적는다

- **규칙**: 백분율·격려·게이미피케이션을 넣지 않는다. 진도바와 달성 연출이 기본값처럼 붙는 영역을 특히 조심한다.
- **근거**: NFR-9 (dry 한 정보 앱). `2026_08_03-corner-3style/GLOBAL.md` 6절.
- **검사**: **불가.** 사람이 읽어야 한다 — 리뷰에서 본다.

### 4.6 한국어 UI, 큐브 표기와 케이스 코드는 영문

- **규칙**: 무브(`R U R'`)·케이스 코드(`LB`)·큐비 이름(`UBL`)은 만국 공통이라 번역하지 않는다.
- **근거**: `2026_08_03-corner-3style/GLOBAL.md` 6절. #15(i18n)의 번역 대상 표도 같은 선을 긋는다.
- **검사**: **불가.** 리뷰에서 본다.

## 5. 렌더

### 5.1 SSR 과 CSR 의 요소 구성·개수·크기가 같다

- **규칙**: `{#if}` 로 화면 요소를 넣었다 뺐다 하지 않는다. 접는 것은 CSS 로 한다.
- **근거**: **이 저장소가 두 번 밟은 함정이다.** 하이드레이션 직후 요소가 생기거나 사라지면 레이아웃이 밀린다 (`2026_08_08-memorize-check/GLOBAL.md` AD-4, `2026_08_20-tracing/GLOBAL.md` AD-14).
- **예외**: 하단 탭바는 라우트마다 다르다. 갈리는 것은 **라우트 사이**이고 한 라우트의 두 시점은 언제나 같다 — `tabsFor` 가 `localStorage` 를 안 읽는 순수 함수인 것이 그 보장이다.
- **검사**: `tests/e2e/memorize-hide.spec.ts` · `tests/e2e/memorize-progress.spec.ts` (SSR 산출물), `tests/e2e/trace-session.spec.ts` (프리렌더 자리).

### 5.2 알고리즘 렌더는 `Alg.svelte` 한 곳

- **규칙**: `{@html}` 을 쓰지 않는다. 프라임 기호는 ASCII `'`(U+0027). 무브 사이에는 실제 공백 텍스트 노드가 들어간다.
- **근거**: 복사했을 때 무브 구분이 유지되어야 한다 (`2026_08_03-corner-3style/GLOBAL.md` D-3, `README.md`).
- **검사**: `tests/e2e/notation.spec.ts`.

## 6. 저장

### 6.1 `localStorage` 키와 스키마 버전을 기능별로 분리한다

- **규칙**: `ui.*` · `memorize.*` · `trace.*`. 한 기능의 스키마가 올라도 다른 기능의 저장을 건드리지 않는다.
- **근거**: `2026_08_20-tracing/GLOBAL.md` AD-13. 0.5.0 롤백이 데이터 안전한 이유가 이것이다 — 새 키만 쓰고 암기 진도를 안 건드린다.
- **검사**: `tests/unit/memorize.test.ts` · `tests/unit/tracing.test.ts`.

### 6.2 데이터의 알고리즘을 코드가 만들거나 고치지 않는다

- **규칙**: 더 짧은 것으로 교체하지 않는다. 기준공식의 개수·이름·순서·방향도 데이터가 정한다.
- **근거**: 시뮬레이터로 3중 검증(메모 방향 / 코너 해결 / 엣지 무영향)을 통과한 값이다. 길이만 보고 최적화하면 엣지 무영향 조건이 깨진다 (`README.md` 주의).
- **검사**: `tests/unit/data-regression.test.ts` (378 케이스 전수).
