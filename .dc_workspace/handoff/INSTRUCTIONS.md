# 3-Style Corner Trainer — 개발 지시서

BLD(눈가리고 큐브 맞추기) 연습용 알고리즘 조회 앱. 케이스 코드(예: `LB`)를 입력하면
해당 커뮤테이터 공식과 그 구조를 즉시 보여주는 것이 목적.

---

## 0. 먼저 읽을 것

- 데이터는 **이미 완성되어 있음**: `3style_ubl_data.json` (378케이스, 176KB)
- **알고리즘을 새로 계산하지 말 것.** JSON의 값을 그대로 신뢰하고 표시만 할 것.
  (모든 알고리즘은 큐브 시뮬레이터로 3중 검증됨 — 메모 방향 일치, 코너 완전 해결, 엣지 무영향)
- 이 앱은 **조회 도구**이지 큐브 솔버가 아님. 큐브 상태 계산 로직 불필요.

---

## 1. 도메인 배경 (구현에 필요한 최소한)

### 버퍼와 케이스 표기

- **버퍼** = UBL 큐비. 스티커 `A`(U면), `E`(L면), `R`(B면).
- 버퍼 스티커 A/E/R은 **케이스 코드에 절대 등장하지 않음** (읽는 위치이지 타깃이 아님).
- **케이스 `XY`의 의미**: 버퍼에 있던 조각 → X 자리로, X에 있던 조각 → Y 자리로,
  Y에 있던 조각 → 버퍼로. 즉 3개 조각의 순환.
- 유효 케이스 수 = **378개**. (버퍼 제외 21개 스티커 중 X, Y를 순서 있게 뽑되,
  X와 Y가 같은 큐비면 3-cycle이 아니므로 제외)

### 두 가지 풀이 방식 (앱의 핵심 기능)

각 케이스마다 **두 가지 알고리즘**이 데이터에 들어 있음:

| 방식 | 설명 | 외울 양 | 길이 |
|---|---|---|---|
| **direct** | 그 케이스 전용 최적 알고리즘 | 378개 전부 | 평균 8.9수 |
| **setup** | 기준공식 10개 + 셋업 | 기준 10개 | 평균 11.2수 |

- **direct**: `[A, B] = A B A' B'` (pure) 또는 `S [A,B] S'` (conj)
- **setup**: 조각을 기준공식의 "입구"로 셋업 → 기준공식 실행 → 셋업 되돌림.
  M2 메서드의 셋업/역셋업과 동일한 구조.

사용자는 학습 단계에 따라 둘 중 하나를 봄. **두 방식을 토글로 전환**할 수 있어야 함.

### 역 트릭 (학습량 절반)

`XY`의 알고리즘을 뒤집으면 정확히 `YX`의 알고리즘이 됨 (378/378 성립 검증됨).

**뒤집기 규칙**: 무브 순서를 거꾸로 + 각 무브 토글. `'`가 있으면 떼고, 없으면 붙이고,
`2`는 그대로. 예: `R U R' U'` → `U R U' R'`

이 규칙은 앱에서 직접 구현해도 되고(간단함), `inverse` 필드로 짝 케이스를 참조해도 됨.

## 2. 데이터 구조

`3style_ubl_data.json`:

```jsonc
{
  "meta": {
    "buffer": "UBL",
    "bufferStickers": ["A", "E", "R"],
    "primarySticker": "A",
    "totalCases": 378,
    "colorScheme": { "U": "W", "D": "Y", "F": "G", "B": "B", "R": "R", "L": "O" }
  },

  "stickers": {
    "B": { "cubie": "UBR", "face": "U" },
    // ... 24개 전부 (버퍼 A/E/R 포함)
  },

  "anchors": {
    "LB": {
      "alg": "R D2 R' U R D2 R' U'",
      "entry1": { "sticker": "L", "cubie": "DFL", "face": "F" },
      "entry2": { "sticker": "B", "cubie": "UBR", "face": "U" },
      "count": 100,        // 이 기준이 담당하는 케이스 수
      "moves": 8
    }
    // 총 10개: LB TU SC NG UN WM NU KD UB KS
  },

  "cases": {
    "LB": {
      "case": "LB",
      "target1": { "sticker": "L", "cubie": "DFL", "face": "F" },
      "target2": { "sticker": "B", "cubie": "UBR", "face": "U" },
      "direct": {
        "alg": "R D2 R' U R D2 R' U'",
        "moves": 8,
        "type": "pure",        // "pure" | "conj"
        "A": "R D2 R'",        // 인서트 파트
        "B": "U",              // 교환 파트
        "S": ""                // conj일 때만 셋업이 들어감
      },
      "setup": {
        "alg": "R D2 R' U R D2 R' U'",
        "moves": 8,
        "anchor": "LB",        // 어떤 기준공식 기반인지. "(직접)"이면 기준 없이 전용
        "S": ""                // 셋업 무브
      },
      "inverse": "BL"          // 역 케이스
    }
    // 378개
  }
}
```

**주의**: `setup.anchor`가 `"(직접)"`인 케이스가 6개 있음 (`CU CW UC UW WC WU`).
셋업으로 어느 기준에도 닿지 않아 전용 알고리즘을 쓰는 케이스. UI에서 이걸 구분 표시할 것.

## 3. 필수 기능

### 3.1 검색 / 조회 (최우선)

- **입력창에 2글자 입력 → 즉시 결과**. 이게 앱의 존재 이유.
- 대소문자 무시. 1글자만 입력하면 그 글자로 시작하는 케이스 목록을 후보로 표시.
- 유효하지 않은 조합(버퍼 스티커 포함, 같은 큐비 조합)은 "해당 케이스 없음"과 함께 이유 표시.
  - 예: `AB` → "A는 버퍼 스티커라 케이스에 등장하지 않습니다"
  - 예: `BN` → "B와 N은 같은 큐비(UBR)라 3-cycle이 아닙니다"
- 모바일에서 쓸 것이므로 **입력이 빨라야 함**. 물리 키보드 입력 + 온스크린 24글자 버튼 둘 다 지원 권장.

### 3.2 결과 표시

한 케이스를 조회했을 때 보여줄 것:

**공통**
- 케이스 코드 (크게)
- 두 타깃의 위치: `L = DFL의 F면` 식으로. 큐비 + 면을 함께.
- 역 케이스 링크 (`BL` 탭하면 그쪽으로 이동)

**direct 모드**
- 알고리즘 (큰 고정폭 글꼴)
- 무브 수
- pure면 `A · B · A' · B'` 4토막으로 구분해서 표시 (색 또는 구분자)
- conj면 `S · [A,B] · S'` 구조 표시
- A는 "인서트", B는 "교환"으로 라벨링

**setup 모드**
- 셋업 S
- 기준공식 이름 + 그 공식
- 기준공식의 입구 2자리 (`입구1: L = DFL의 F면`)
- 전체 알고리즘 (셋업+기준+역셋업을 무브 상쇄까지 적용한 최종형)

### 3.3 기준공식 브라우저

- 10개 기준공식을 담당 케이스 수 순으로 나열 (LB 100개 → TU 83 → SC 60 → ...)
- 각 기준을 탭하면 그 기준을 쓰는 케이스 목록
- 상위 3개(LB/TU/SC)만으로 243개를 커버한다는 점을 UI에 드러낼 것 (학습 우선순위)

## 4. 있으면 좋은 기능 (우선순위 순)

1. **즐겨찾기 / 학습 상태 표시** — 케이스별로 "안 봄 / 학습중 / 익힘" 표시.
   로컬 저장. 기준공식별 진도율 표시.
2. **랜덤 퀴즈** — 케이스 코드를 보여주고 알고리즘을 떠올린 뒤 정답 확인.
   틀린 케이스를 다시 출제하는 간단한 반복 로직.
3. **필터** — 무브 수별, pure/conj별, 기준공식별, 학습 상태별.
4. **알고리즘 애니메이션** — 큐브 3D 렌더링. 나중에.

## 5. 기술 요구사항

- **오프라인 우선.** 데이터가 176KB뿐이라 전부 번들에 포함. 네트워크 요청 없음.
- **PWA로 만들 것.** 폰 홈화면에 추가해서 앱처럼 쓰는 게 목표.
- **모바일 우선 반응형.** 한 손 조작 가능해야 함. 주요 액션은 엄지 닿는 위치.
- 프레임워크는 자유. 다만 데이터가 정적이므로 무거운 상태관리는 불필요.
- **다크 모드 지원.** 큐빙은 밤에 하는 경우가 많음.

### 표기 렌더링 주의

- 큐브 표기는 **고정폭 글꼴** 필수. `R'`와 `R`이 명확히 구분돼야 함.
- 프라임(`'`)을 타이포그래피 따옴표로 자동 변환하지 말 것. 반드시 ASCII `'`.
- 무브 사이 공백을 유지할 것. 줄바꿈 시 무브 중간에서 끊기지 않게 (`white-space: nowrap` 단위로).

## 6. 확장 계획 (지금은 구현하지 말고 구조만 열어둘 것)

이 앱은 나중에 큐브 학습 앱으로 확장할 예정. 아래를 염두에 두고 데이터 레이어를 분리할 것:

- **UFR 버퍼 코너 3-style** — 같은 스키마로 별도 JSON. 버퍼 스티커만 `C/M/J`로 다름.
- **엣지 3-style** — 케이스 수가 더 많음(440+). 같은 구조.
- **M2 엣지 / OP 코너** — 기존 메서드 참조표.
- **패리티 처리** — 현재 UBL 버퍼 + M2 엣지 조합에서는 코너 letter가 홀수면
  남은 1개를 OP Y-perm으로 처리함. 이 규칙을 안내하는 페이지.

따라서 **`buffer`와 `pieceType`(corner/edge)을 키로 하는 데이터 로더**를 처음부터
분리해두면 나중에 추가가 쉬움. 지금은 corner/UBL 하나만 구현.

## 7. 검증 (구현 후 반드시 확인)

- [ ] 378개 케이스가 모두 조회되는가
- [ ] `LB` 조회 → `R D2 R' U R D2 R' U'`, 8수, pure, A=`R D2 R'`, B=`U`
- [ ] `CU` 조회 → setup 모드에서 anchor가 `(직접)`으로 표시되는가
- [ ] `AB`, `EB`, `RB` 같은 버퍼 스티커 입력이 적절히 거부되는가
- [ ] `BN`(둘 다 UBR), `CM`(둘 다 UFR) 같은 동일 큐비 조합이 거부되는가
- [ ] direct ↔ setup 토글이 모든 케이스에서 동작하는가
- [ ] 역 케이스 링크가 올바른 케이스로 이동하는가 (`LB` ↔ `BL`)
- [ ] 오프라인에서 동작하는가 (네트워크 끊고 테스트)
- [ ] 프라임 기호가 ASCII `'`로 렌더링되는가 (복사해서 확인)

## 8. 참고: 도메인 용어 사전

| 용어 | 의미 |
|---|---|
| 버퍼 (buffer) | 항상 기준이 되는 조각. 여기선 UBL |
| 커뮤테이터 (commutator) | `[A,B] = A B A' B'`. 3개 조각만 순환시키는 구조 |
| 컨주게이트 (conjugate) | `S [A,B] S'`. 셋업으로 조각을 옮긴 뒤 커뮤테이터 적용 |
| 인서트 (insert, A파트) | 평면 밖 조각을 평면 안 빈자리로 데려오는 3수 덩어리 |
| 교환 (interchange, B파트) | 한 무브로 두 조각 자리를 맞바꿈 |
| 셋업 (setup, S) | 타깃 조각들을 기준공식의 입구 자리로 옮기는 무브 |
| 입구 (entry) | 기준공식이 실제로 순환시키는 두 자리 |
| Speffz | 24개 스티커에 A~X를 할당하는 표준 레터링 |
| 3-cycle | 3개 조각의 순환. 코너 3-style의 기본 단위 |

## 9. 데이터 신뢰성 메모

`3style_ubl_data.json`의 모든 알고리즘은 다음을 통과함:

1. **메모 방향 검증** — 알고리즘이 푸는 상태에서 버퍼가 X를 읽고, X 자리가 Y를 읽는가
2. **코너 해결 검증** — 해당 스크램블에 알고리즘 적용 시 코너가 완전히 풀리는가
3. **엣지 무영향 검증** — 엣지를 전혀 건드리지 않는가 (엣지 먼저 푸는 순서에서 필수)

378/378 통과. 추가로 역트릭(`XY` 뒤집기 = `YX`)도 378/378 성립 확인.

**이 데이터를 재계산하거나 "최적화"하려 하지 말 것.** 같은 3-cycle을 만드는 커뮤테이터는
여러 개 존재하며, 여기 실린 것은 길이 우선 + 손가락 친화도(B/F면 무브 페널티) 기준으로
선정된 것임.
